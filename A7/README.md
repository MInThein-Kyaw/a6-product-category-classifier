## Run in VS Code / PowerShell

Open **Platform assignment 6** as the workspace and open a PowerShell terminal.
The existing root virtual environment can be reused:

```powershell
Set-Location 'D:\Platform assignment 6'
.\.venv\Scripts\python.exe -B A7\evaluate.py
.\.venv\Scripts\python.exe -B A7\write_reports.py
.\.venv\Scripts\python.exe -B A7\verify.py
```

The installed Python launcher also works:

```powershell
py -3.13 -B A7\evaluate.py
py -3.13 -B A7\write_reports.py
```

`-B` prevents bytecode files from being created. The wrapper also disables bytecode
writing before importing A6. No API keys, web server, or network inference is needed.
The recorded environment used Python 3.13.14 / scikit-learn 1.9.1. If dependencies
are unavailable, create an environment inside A7 rather than altering root files:

```powershell
py -3.13 -m venv A7\.venv
.\A7\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\A7\.venv\Scripts\python.exe -B A7\evaluate.py
.\A7\.venv\Scripts\python.exe -B A7\write_reports.py
```

Dependency installation requires internet. Do not submit `.venv` folders.

## Frozen expectations

The original preparation command was:

```powershell
py -3.13 -B A7\evaluate.py --freeze
```

It ran before A7 evaluation and saved `eval_cases.lock.json` and
`freeze_evidence.txt`, including dataset and original root-file hashes. The lock is
already supplied. **Do not rerun freeze, delete the lock, or revise expectations
after viewing results.** Subsequent evaluation verifies that hash before and after
the run. Freeze mode refuses to replace an existing lock and does not fit/predict.
Some input products were previously demonstrated in A6; this is not a blind holdout.

## How evaluation works

- Exactly 10 cases: 3 normal, 3 edge, 2 fallback, 2 difficult. Category plus status
  must both match the frozen expectation to PASS.
- Baseline runs the original A6 method at 0.45. The isolated A7 wrapper changes its
  threshold to 0.40 and reuses the exact same fitted pipeline object. Its reason
  string displays the new threshold; original validation/error logic is reused.
- A wrapper at 0.45 is first compared with the original on all ten cases.
- T08 deliberately injects a prediction exception using a temporary mock. This is
  labeled simulation, not a real outage; both versions use the same fault.
- Each case/version gets three warmups and 30 measured calls, with alternating
  version order. Latency is measured around the classifier call with
  `perf_counter_ns`. Per-case latency is the median. P95 is nearest rank across
  300 samples per version (sorted observation 285). JSON includes every timed sample.
- Training/imports/retrieval/printing/mock setup are excluded. Failure and invalid
  input calls are included in the workload. Wrapper overhead and measurement noise
  are included. This is not HTTP, cold-start, or production-load latency.
- API cost is N/A. Hardware/electricity/operating costs are not measured.
- Root A6 file hashes and the frozen dataset hash are checked before and after.

`retrieval.py` selects up to two positive-overlap knowledge records by description
tokens, with deterministic ID tie-breaking. `retrieval_demo.json` records actual
selected context and a local decision. The context is application metadata; it is
**not passed into the A6 classifier features**. Integrating context into a model
would be future work and is not a second improvement in this experiment.

## Outputs and reruns

`evaluate.py` saves baseline/improved JSON and readable text results,
`retrieval_demo.json`, `terminal_output.txt`, and `integrity_check.json` inside A7.
`write_reports.py` rebuilds `improvement.md` and the nine-section `A7_Report.md` from
those files without running predictions. New runs replace A7 measurement files;
timings naturally vary, so regenerate the report after rerunning. The frozen
expectations and original A6 results are never rewritten. A failed case is valid
evidence and is not a script execution error; integrity failures stop the script.

`verify.py` performs separate artifact checks and explicitly simulated threshold
boundary/failure checks, saving `verification.txt`. These checks are not added to
the ten-case evaluation accuracy or latency measurements.

The first recorded comparison was 90% before and 90% after. T09 was a safe abstention
that failed its Electronics/automatic-routing target. There was no observed routing
change. The lower threshold should not be presented as an accuracy gain.
